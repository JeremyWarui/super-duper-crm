How the four compare

Cost and fit for this codebase: React 19 + Vite, about 2,900 lines of JSX and 450 class names, one stylesheet today.

OptionNew dependenciesWork to adoptBundle added (approx.)Best atWatch out for
A · Current CSSNoneDone0Zero cost, one file to rethemeEvery new widget (dropdown menu, date picker, combobox) is hand-built
B · shadcn/uiTailwind v4, Radix, cva, clsx, tailwind-merge, lucide-reactHigh: rewrite most className uses and delete index.css. About 3 to 5 days with screenshot checks20 to 40 KB gzip for the components usedForms, dialogs, dropdowns, comboboxes and tables, with accessibility built inMonochrome by default, so the campaign green needs theming. You own the copied component code.
C · Tremor / TailwindTailwind, Radix, Recharts (for charts)High: the same Tailwind rewrite as B, plus chart wiring60 to 120 KB gzip once charts are inAnalytics: trends, bar lists, trackersCharts need time-series data the API doesn't return yet. Heavier on phones in the field.
D · CSS, dark railNone (inline SVG icons)Low: re-theme index.css, add icons and counts to the nav. About 1 dayA few KB of iconsDensity and a "command centre" feel for managersCompact text is harder for mobilizers on phones; keep public pages (join, withdraw) roomy.
Recommendation. Stay on plain CSS and take the best ideas from the others without their dependencies: D's navigation icons, counts and user block; B's card header icons and the change line under each metric ("+1,204 this week"); C's unit-status tracker strip. Move to B (shadcn + Tailwind) only if the roadmap fills up with complex form controls such as searchable selects, date pickers and multi-step dialogs. Take C only once the API serves time series worth charting.

All numbers on the mock screens are sample data. Bundle sizes are estimates, not measured in this repo. Variants B and C load Tailwind from its CDN for this preview only.
